# `/skill:sdlc-duplication-scan`

Find every place the repository implements one thing more than once, or houses a
module at the wrong tier, and destroy every candidate that cannot survive a
skeptical staff engineer. The output is a decision document, not a list of grep
hits.

Usage:

- `/skill:sdlc-duplication-scan` — scan the whole repository.
- `/skill:sdlc-duplication-scan packages solutions/foo` — restrict to those roots.
- `--workdir <dir>` — where all state lives (default `.scan/`).
- `--max-rounds <n>` — hard cap on adjudication rounds (default 5).
- `--min-copies <n>` — sites a finding needs before it can be accepted without a
  defect-echo (default 3).

Reference material, loaded on demand:

- `${CLAUDE_PLUGIN_ROOT}/skills/sdlc-duplication-scan/references/schema.md` —
  finding and objection schemas, the charter shape, the Adversary checklist,
  the Arbiter rubric, the convergence criteria.
- `${CLAUDE_PLUGIN_ROOT}/skills/sdlc-duplication-scan/references/prospector.md`,
  `adversary.md`, `arbiter.md` — the protocol each role reads in full.
- `scripts/sdlc duplication-scan` — the deterministic ledger
  ops (`--advanced --help` lists them). Each ends its output with
  `DUPLICATION-SCAN-LEDGER-OK cmd=<op> findings=<n> objections=<n>` and exits
  non-zero on bad input. An `unknown ids:` line names ids a charter cited that
  the ledger does not hold; treat them as that charter's error.

## The rules that govern everything

**Evidence or silence.** Every claim — a proposal or an objection — cites
`path:line-range`, a commit, a build-graph edge, or a command with its output.
An assertion without a citation is struck, whoever made it.

**Read the code; a name is a lead, never a finding.** Two functions called
`formatCurrency` may be unrelated; two called nothing alike may be identical.

**The burden of proof is on extraction.** Duplication is not a defect by itself;
decoupling is a real benefit. Copies that differ because two products need
different behaviour are variation, and merging them creates a conditional mess.

**Separate contexts for opposing roles.** A Prospector and the Adversary that
attacks its findings never share a context window: the Adversary receives the
written finding and the repository, and re-derives the evidence itself. One agent
never plays both roles.

**Name the concept.** A proposal targets a named package or module (`atomic-write`,
`useJobRun`, `determined-doubles`), never a `shared`, `common`, `utils`, or
`core` bucket.

**Consult settled ground first.** A candidate that restates an open decision,
task, or backlog item is not a finding; dismiss it and cite the id.

**Read-only on the source tree.** Write only under the work directory. Take no
branch, stash, build, or test action. Two exceptions: the unshallow fetch in
step 0, which only adds objects, and installing the clone detector step 1 runs.

## 0. Resolve scope and open the work directory

1. Read the arguments; record `WORKDIR`, `MAX_ROUNDS`, `MIN_COPIES`, and the
   scope roots (default: the whole repository).
2. Initialise the ledger:

   ```text
   scripts/sdlc duplication-scan init \
     --workdir <WORKDIR> --param MAX_ROUNDS=<n> --param MIN_COPIES=<n>
   ```

3. Unshallow the history when the clone is shallow (`git rev-parse
   --is-shallow-repository`); co-change and defect-echo evidence needs it.

## 1. Cartography (round 0)

Produce `<WORKDIR>/map.md` before any candidate exists. Do this yourself with
tools, or delegate one `cartographer` charter (charter shape in `schema.md`).
The map carries, with the commands that produced each table:

1. **Topology** — products, solutions, packages, apps; which deploy
   independently; release cadence and any publish channel.
2. **Dependency graph** — package→package edges from every manifest
   (`package.json`, `Cargo.toml`, `go.mod`, `pyproject.toml`, workspace files);
   include semver-range edges between in-repo packages; flag cycles and
   packages with exactly one or zero consumers.
3. **Ownership** — CODEOWNERS, or `git shortlog -sn` per directory; when the
   repository has one author, say so and evaluate ownership as *subtree or
   planning unit*.
4. **Volatility** — commits, authors, and lines changed per directory over the
   history window; note directory moves, because co-change counts must follow
   renames.
5. **Boundaries that already leak** — deep relative imports that resolve outside
   their own package root, copied configuration, duplicated CI steps.
6. **Exclusions** — generated code, vendored code, fixtures, migrations, data
   vaults, and any tree a decision already marks for deletion — with the reason.
7. **Settled ground** — the decisions, milestones and tasks that already
   adjudicate a consolidation, so later rounds cite them instead of re-arguing.

Run a clone detector where one exists for the language — `jscpd --min-tokens 60`,
or PMD CPD's equivalent — and save its pairs under `<WORKDIR>/data/` as leads
only.

## 2. Prospect (expand)

1. Split the scope by natural seam — language, product, package, layer — into
   at most six `prospector` charters, and dispatch them concurrently in one
   message. Each charter names its scope, its single question, the leads from
   the clone detector and the map, and `depth_remaining`.
2. Point every Prospector at `prospector.md` and `map.md`; it writes
   `<WORKDIR>/rounds/r<N>/<charter_id>.json` and returns a summary only.
3. Spot-check at least one cited line range per returned finding before
   merging; you own a child's error once you forward it.
4. Fold findings that two charters reached from different sides, then assign
   ledger ids:

   ```text
   scripts/sdlc duplication-scan merge-findings \
     --workdir <WORKDIR> --round <N> [--fold <secondary-id>=<primary-id>]... <charter.json>...
   ```

In round 1 cast wide. In later rounds work the coverage gaps each charter
reported as `not_reached`, the evidence questions the Arbiter named for
contested findings, and — when the previous round's calibration was above one
third — a tightened threshold: at least `MIN_COPIES` sites or a cited
defect-echo, the target's own docs read before naming it, the seam costed rather
than the call sites.

## 3. Attack (falsify)

1. Slice the open findings (`proposed` and `contested`) by cluster into at most
   six `adversary` charters; give each only its slice of the ledger and the
   repository — never a Prospector's charter file.
2. Point every Adversary at `adversary.md`; it runs the full checklist in
   `schema.md`, files objections with evidence, and returns a `survived` entry
   with a `tried` list for every finding it failed to falsify.
3. From round 2 on, also dispatch a re-attack of every `accepted` finding in its
   amended form, and require the Adversary to file self-refutations of its own
   earlier objections when new evidence contradicts them.
4. Merge:

   ```text
   scripts/sdlc duplication-scan merge-objections \
     --workdir <WORKDIR> --round <N> <adversary.json>...
   ```

## 4. Adjudicate

1. Dispatch `arbiter` charters over the same slices; an Arbiter authored neither
   side and opens the repository only for a disputed fact.
2. Point each at `arbiter.md`; it sets a verdict per finding from the rubric,
   a disposition per objection, `rank_inputs` (benefit, confidence, cost), the
   round delta, gaps for the next round, and the Prospector calibration.
3. Apply and read the convergence checklist:

   ```text
   scripts/sdlc duplication-scan apply-verdicts \
     --workdir <WORKDIR> --round <N> <arbiter.json>...
   scripts/sdlc duplication-scan status \
     --workdir <WORKDIR> --round <N>
   ```

4. Append the round to `<WORKDIR>/round-log.md`: charters issued, delta,
   objections sustained and overruled, and the convergence decision with its
   reason.

## 5. Decide whether to continue

Exit when `status` reports a quiet round for `STABLE_ROUNDS_TO_EXIT` (default 2)
consecutive rounds: no new
finding above confidence 0.5, no status change, no new fatal or material
objection, every finding terminal, and a failed-falsification report on every
accepted finding in its final form. Continue when any objection is unresolved,
when a verdict changed, when a listed product, package or language has no
Prospector coverage yet, or when calibration is above one third (tighten the
Prospector and rerun). When two consecutive rounds produce identical objections
with no new evidence, mark the point `contested` and stop arguing it. Narrow late
rounds to what is new: a re-attack of amended acceptances, an Adversary pass over
fold-ins the Arbiter verified but no Adversary attacked, a single Arbiter
confirmation. On reaching `MAX_ROUNDS`, stop and list every non-terminal finding
with what would settle it; never promote unfinished work to `accepted` to close
the loop.

## 6. Write the deliverables

1. `<WORKDIR>/report.md` — executive summary (generated, survived, the aggregate
   case); accepted findings ranked by benefit × confidence ÷ cost, each with API
   surface, consumers, dependency edges, migration steps, owner, and the
   objections it survived; contested findings with both cases verbatim; deferred
   findings with the exact question a human must answer; rejected findings with
   one-line reasons; a coverage statement (scanned, excluded, not reached and
   why); a confidence statement (where the analysis is weakest). Start from:

   ```text
   scripts/sdlc duplication-scan report-tables \
     --workdir <WORKDIR>
   ```

2. `<WORKDIR>/pilot-<id>.md` — for the single highest-ranked accepted finding
   only: a numbered one-PR migration plan a developer can execute, with
   preconditions, exact edits by file, the validation commands, a byte-identity
   or behaviour check, risks and rollback, and a PR description draft. Delegate
   it to a `specialist` charter that reads the finding and the target's API.
3. Commit only the decision documents — `report.md`, `round-log.md`, `map.md`,
   `pilot-<id>.md`. In a project with sdlc notes, land them as `genre:
   analysis` notes (`scripts/sdlc note create`): the report
   as the hub, the other three as sub-documents whose `parent` is the hub.
   Elsewhere, put them where the repository keeps analysis documents.
   `ledger.json`, `rounds/` and `data/` are run state: megabytes of raw charter
   output that no reader opens and that `init` then collides with on the next
   run. Gitignore the work directory. This is the same split as
   `solutions/ontological/conventions/skill-reports.md` — judgment committed,
   run state not — reached without that convention's render pipeline, because
   the ledger, not a one-shot payload, is this skill's data contract.

## 7. Verify before reporting

1. `status` reports zero `proposed` findings, zero unresolved fatal or material
   objections, and names the exit clause.
2. Every accepted finding in `report.md` cites at least `MIN_COPIES` sites or a
   defect-echo commit, names a concept target, and carries a countable migration
   cost.
3. Every deferred finding states its human question; every rejected finding
   states its reason.
4. `git status --porcelain` shows changes only under `<WORKDIR>` and the
   committed decision documents.

Emit exactly one terminal marker:

- `DUPLICATION-SCAN-DONE workdir=<dir> rounds=<n> accepted=<a> rejected=<r>
  deferred=<d> contested=<c> exit=<clause>`
- `DUPLICATION-SCAN-STOPPED workdir=<dir> rounds=<n> reason=max-rounds
  non_terminal=<ids>`
- `ERROR reason="..."`

Front-loaded rules, repeated: evidence or silence; separate contexts for
Prospector and Adversary; the burden of proof is on extraction; name the concept;
read-only outside the work directory.

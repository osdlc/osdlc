# Changelog

## Unreleased

- `.github/workflows/cursor.yml` is callable from other repositories (`workflow_call`): a short caller with `secrets: inherit`. Settings come from the calling repository's variables (`PR_AGENT_TRIGGER_USERS`, `PR_AGENT_APP_CLIENT_ID`, `PR_AGENT_ENVIRONMENT`), each overridable by an input; the App key is the secret `PR_AGENT_APP_PRIVATE_KEY` and is passed as `client-id`, not the deprecated `app-id`. The workflow fetches this action and `pr-apply` from its own commit, so pinning the workflow pins them.
- Run mode: `@cursor /<plugin>:<skill> [args]` runs any installed skill and posts its output (marker `cursor-run`). `@cursor <free text> --apply` runs a free-form instruction the same way (edits allowed, same patch artifact and push job; commit `cursor: instruction from #<pr> comment`); free text without `--apply` is still an answer. `--apply` lets the agent edit files; the agent job uploads the edits as a patch artifact (output `apply-patch`) and a separate job (action `pr-apply`) validates and pushes it. The agent job has no push token. Answer and review modes are unchanged.
- A key that is out of credit now falls through to the next key, like an authentication failure; the list order is the priority. The usage-limit text is unverified.
- First version: `@cursor` answers and `@cursor review`, a list of API keys, done and failed markers (`cursor-answer`, `cursor-review`), read-only through ask mode and a temporary permission file, the craft code-review skill inlined into the review prompt, and a `marketplaces` input (plugins are not supported on cursor).

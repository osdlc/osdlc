First release. `@osdlc/ecosystem` holds the settings every osdlc tool shares, one module per concern.

- The package entry gives the family's directories: `OSDLC_VENDOR_DIRS` (`osdlc`, moved by `OSDLC_ROOT` and `OSDLC_<HOME>_DIR`) and `osdlcDirs()`, pinned to the Xdg convention, so `~/.config/osdlc` on Linux and macOS. `osdlcDirs().standalone('osdlc').config().path` is that folder, and a tool passes `vendorDirs: OSDLC_VENDOR_DIRS` to config-layers' `machineConfigFile` to keep its own file under `osdlc/<tool>/`.
- `@osdlc/ecosystem/repositories` reads and writes `repositories.yaml` in the osdlc config home. Its `roots` list the directories that hold a person's checkouts. `repositoriesFile()` is the handle: `OSDLC_REPOSITORIES` moves the file and must be absolute, the schema is strict, and `writeRoots(roots, { etag })` is a compare-and-swap that edits only the `roots` entry, keeping every other line and its comments, and throws `WriteConflictError` (re-exported from `@osdlc/etag-write`) when the file changed since it was read. It holds the lock file `repositories.yaml.lock` (`@osdlc/file-lock`) while it reads, checks and writes, so of two processes writing over the same read, one writes and the other gets the conflict. A lock is taken over once its holder has exited, or once it is 10 minutes old.
- `resolveRoots()` gives the roots to scan. An absolute entry or one starting `~` is a root, a relative entry is dropped with a warning naming the file, a missing directory is skipped, and `roots: []` scans nothing. With no file or no `roots`, `defaultRoots()` uses the directory that holds the caller's main checkout, or the one above it when that directory is named after the owner in the caller's `origin`. It never steps up to the home directory or above it: a checkout directly in home uses home, and one that is home itself gets none.
- `parseRepoTarget('host/owner/name')` (or `'owner/name'`) gives the target as a typed-git `RepoCoordinate`, and throws on any other shape, so a tool can check a `--repo` value before it scans: `locateCheckout(parseRepoTarget(value))`.
- `CheckoutLocator` and `locateCheckout('owner/name')` find every checkout whose `origin` names a repository, through `@osdlc/typed-git`'s `scanForCheckouts`, `readRemote` and `sameRepo`. Each repository's main checkout is returned once, linked worktrees included. A locator scans the roots once for all its targets, and gives the roots it searched, the file's path, and `depthLimited`, the directories the walk left unopened at `maxDepth`, for a caller's messages. A directory the walk found counts only when git, run in it, says it is the top of a working tree, so a broken `.git` cannot answer with the repository around a root. Every git call the package makes unsets an inherited `GIT_DIR` and the other variables that pick a repository, so the default roots and the locator give the same answer inside a git hook. A bare store with its worktrees beside it (`proj/.git` pointing at `proj/.bare`) is not found yet.

Linux and macOS are tested and block a release. Windows is tested in the repository's Windows tier-2 workflow, which reports but does not block.

"@osdlc/repo-cleaner": minor

Worktrees with submodules can now be cleaned up. Plain `git worktree remove` refuses any worktree with a checked-out submodule, or with a submodule git dir left behind by `git submodule deinit`, so `apply` used to fail on every such worktree. The sweep now reads each submodule, nested ones included, and each left-over submodule git dir, and a worktree whose submodules are clean and pushed is `safe-to-delete` with a `git worktree remove --force` command (`facts.submodules_force`). Just before that remove, `apply` checks the worktree's own files and every submodule again, since `--force` skips git's own check, and refuses if anything changed.

A submodule is judged as part of its worktree, under the same authorizations. A linked worktree's submodules keep their history in the worktree's own git dir, so removing the worktree deletes it: a submodule's commits on HEAD or a local branch that no remote-tracking ref holds, and its stashes, make the row require `abandon-unmerged`, as the worktree's own unpushed commits do, and its modified or untracked files require `discard-changes`. One grant on the worktree row covers its submodules. A new blocker, `submodule-unreadable`, holds back a worktree with a submodule that could not be read. Skip-worktree or assume-unchanged files and nested repositories inside a submodule count toward `hidden-index-flags` and `nested-repository`. A worktree whose directory is gone but whose git dir keeps unpushed submodule work needs `abandon-unmerged` to be pruned, and a `worktree prune` that would delete such work from a gone worktree the run was not granted is refused (the closing prune of a run is skipped and says why). Each row's `facts.submodules` lists what was found, and is part of the plan fingerprint, so a submodule that changes after the plan drops the row.

The library exports `inspectSubmodules(git, worktree, { gitDir })`, which returns a `SubmoduleReport`: every submodule with its head, git dir, dirty-file, unpushed-commit and stash counts, whether a remove needs `--force`, and the `dirty`, `unpushed` and `unreadable` subsets. `submoduleHazards(report, { discard, abandon })` lists, one sentence each, what a forced remove would lose that the grants do not cover; `worktreeGitDir(commonDir, worktree)` finds a worktree's private git dir, even once its directory is gone; `submoduleFacts(report)` gives the `facts.submodules` rows.

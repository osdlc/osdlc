Security fixes. Upgrade if you run `way` in repositories you did not write.

- The installed `way` no longer runs code from the directory you stand in. It used to hand off to any directory above the cwd that had a `src/cli.ts`, and ran it under Bun before trust was checked. It now hands off only to the checkout `WAY_HOME` names (an absolute path) or `way dev link` linked, and only when that checkout's `package.json` is named `@osdlc/wayfinder`. That checkout runs under Bun with `--no-env-file` and an empty config, so the `.env` and `bunfig.toml` of the directory you stand in can no longer set the environment or preload code. `WAY_CWD_DEV` no longer does anything. If you develop wayfinder, run `way dev link` in your checkout once. `way dev` still works but no longer shows in `way --help`.
- A relative `WAYFINDER_CONFIG` (or `WAYPOST_CONFIG`) is now ignored with a warning, and the XDG path is read. Run from the repository root, a relative value named a file in the repository as your user config, which can turn execution on and load tools. Use an absolute path, or `~/`. A relative `XDG_CONFIG_HOME`, `XDG_STATE_HOME` or `XDG_CACHE_HOME` is ignored, as the XDG spec says, and a relative `HOME` counts as unset, so the user config, trust store, cache and dev link are never looked up under the cwd.
- Detection and the `origin` owner lookup run the `git` found on absolute `PATH` entries only, so a `git` the repository ships is never run through a relative `PATH` entry or, on Windows, the current folder. The owner lookup also runs git with `core.fsmonitor` off. Clipboard and browser helpers are found the same way.
- The terminal UI, `--list`, `query`, the `trust`, `config`, `providers` and `dev` output, the `--serve` summary and every stderr line now replace control characters (C0, DEL and C1) and bidi controls (U+202A-202E, U+2066-2069) in repository text with U+FFFD. A task name or doc comment could carry escape sequences that write the clipboard or set the window title, or text that displays in a different order from what runs. Copied commands get the same text. `--json` keeps every value exact and now writes DEL, C1 and bidi controls as `\u` escapes, so it is safe to print to a terminal.
- A `trust.owners` entry now matches the host as well as the owner. A bare `my-org` means `github.com/my-org` and no longer trusts a clone from `gitlab.com/my-org` or `bitbucket.org/my-org`. To trust an owner on another host, write `gitlab.com/my-org`. Owner trust believes the repository's own `.git/config`, so it fits clones you made yourself; `trust.paths` is the stronger form. The docs now say so.

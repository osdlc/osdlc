Use the `xdg` folders on macOS as on Linux, so on macOS the config is `~/.config/workstation-cleaner/config.json` and receipts and the log are under `~/.local/state/workstation-cleaner/` (Windows keeps its own folders). A config left in `~/Library/Application Support/host-cleaner/` is not read, and a run without `--config` warns about it on stderr; move it to `~/.config/workstation-cleaner/`. While it is the only config, `clean` without `--dry-run` refuses with exit 2, naming both paths, since its `ignore` list would not apply. Receipts and the log from versions up to 0.3 are not moved: they stay in `~/Library/Application Support/host-cleaner/receipts/` and `~/Library/Logs/host-cleaner/`. `workstation-cleaner config` prints the config file it looked for and whether it exists. Every command refuses a folder variable it cannot use, such as a non-empty `WORKSTATION_CLEANER_CONVENTION` other than `native` or `xdg` or a relative `WORKSTATION_CLEANER_CONFIG_DIR`, with exit 2. When `HOME` is unset, empty or relative the OS account's home is used, for the folders and for `~` in `ignore`; a target that starts with `~` takes it only when `HOME` is unset, and is refused with exit 1 when `HOME` is set but empty or relative, so it never sweeps the account's real folder; and `XDG_CONFIG_HOME` with `XDG_STATE_HOME` place the folders without one; with neither, a command that needs the folders exits 1, while `clean --dry-run` does not need them; a `~` in a target or ignore entry with no home is refused with exit 1, not read some other way. On Windows `~\` is expanded as `~/` is, so an ignore entry written `~\dev\keep` covers that folder. With `XDG_CONFIG_HOME` alone and no home, the commands that only read the config (`status`, `plan`, `plugins`, `config`, `clean --dry-run`) read it there. Under a test runner, or with `WORKSTATION_CLEANER_REQUIRE_OVERRIDE` set, tiered-dirs' test rules apply to the CLI's own folders when it runs on `process.env`; an env passed to `main()` is read as given.

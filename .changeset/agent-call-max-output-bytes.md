Add `maxOutputBytes` to `AgentCallSpec`: a cap on the bytes read from each output stream, stdout and stderr. It counts the bytes the agent wrote, so output that is not valid UTF-8 can decode to a longer string. A stream that passes it stops the agent's process group as a timeout does (SIGTERM, then SIGKILL after 5s), and `callAgent` resolves `ok: false` with the new `CallError` reason `output-limit`, whose `detail` names the stream. The output read so far stays in `raw`, truncated to the cap on a UTF-8 character boundary, and the new `RawProcessOutput.outputLimit` names the stream that passed it. A timeout or abort that came first stays the cause, and `outputLimit` still marks a stream it truncated. `Infinity` means no cap and a fraction rounds up; `0`, a negative value or `NaN` makes `callAgent` reject with a `RangeError`, and a value that is not a number with a `TypeError`, the same rule as `@osdlc/command-seam`. Output is now read as bytes and decoded with the same streaming UTF-8 decoder as before, so collected text is unchanged.

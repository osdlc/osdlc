A lookup that fails costs its evidence, not the repository. A pull request listing the provider cannot make, such as `gh pr list` for a repository the signed-in account cannot see or that no longer exists, used to turn the whole repository into an error row with no rows. Its worktrees and branches are now judged on git evidence, the provider status carries `listError`, a row with no PR says the lookup failed rather than that none was found, and the repository carries a note. `--offline` now reads remote branches from the remote-tracking refs on disk, as documented, instead of calling `git ls-remote`, so an offline sweep never contacts the remote. After a fetch, a `git ls-remote` that fails falls back to the refs the fetch just wrote, with a note on the repository and on each remote row. A failed fetch still fails the repository. `RepoSweep` has a new `notes` field: one sentence for each lookup the sweep judged without, shown under the repository's header in the text and summary reports, in the JSON, and on stderr for `--format commands`, `plan` and `clean`. `lookupPrs` returns the pull requests together with the reason a listing failed. A `PrProvider` reports a failure by returning null or by throwing.

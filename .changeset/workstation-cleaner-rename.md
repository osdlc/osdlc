Rename `@osdlc/host-cleaner` to `@osdlc/workstation-cleaner` (#1032). The command is now `workstation-cleaner`; the config, state and log folders are named `workstation-cleaner` (`~/.config/workstation-cleaner/config.json`, `~/.local/state/workstation-cleaner/`); the variables are `WORKSTATION_CLEANER_*`; the entries are `@osdlc/workstation-cleaner/plugin` and `@osdlc/workstation-cleaner/testing`; the descriptor schema is `https://unpkg.com/@osdlc/workstation-cleaner/schemas/descriptor-1.json`; and the core's own refusals say `by: workstation-cleaner`. Nothing under the old name is read or moved. A config in the old `host-cleaner` folder (`~/.config/host-cleaner/`, or `~/Library/Application Support/host-cleaner/` on macOS), and any `HOST_CLEANER_*` variable, make every command warn. `clean` without `--dry-run` refuses with exit 2 while one of the variables is set, or while the old config is the only one and no `--config` is given: move the file to the new folder, and rename or unset the variable.

# `/pr-stats`

Usage:

- `/pr-stats <pr>` measures a pull request (number, `#number`).
- `/pr-stats --base <ref>` measures the current branch against `<ref>` (default `origin/main`).
- `--write` puts the table in the PR's body. `--detail` adds the per-file list. `--json` prints the
  structured report.

Scope: measures and reports a diff. It never judges the change, never edits code, and writes only
the PR body, and only on `--write`.

Inputs: a PR number, or a checkout with the branch to measure; `git` always, `gh` (authenticated)
for a PR. Output: a markdown block between `<!-- sdlc-pr-stats:start -->` and
`<!-- sdlc-pr-stats:end -->`, or the same data as JSON.

## Steps

1. Run the script that ships beside this note, from inside the repository:

   ```text
   node <skill-dir>/pr-stats.mjs [<pr>|--base <ref>] [--detail] [--json]
   ```

   Without a PR it diffs `<ref>...HEAD`, so commit first; uncommitted work is not measured.
2. Read the output top down:
   - **Lines table.** Added, removed, net by Code, Comments, Blank / whitespace, Prose / docs.
     Generated files (bundles, lockfiles, `packs/`, `*.min.*`) are left out of it and counted in
     the file-group table, so a regenerated bundle does not hide the real change.
   - **Change categories.** Every file is in exactly one. A new test file is `added`, not
     `tests`. `formatting` means the change vanishes once whitespace is removed; `comments`
     means every changed line is a comment or blank.
   - **Dependencies and Exported API.** Added, removed and bumped dependencies from
     `package.json` and `Cargo.toml`; added, removed (`-`) and changed (`~`) exported names, with
     `Class.member` entries for public members of exported classes and interfaces.
   - **Complexity.** Cyclomatic complexity before and after per function. The table lists the
     five biggest movers; unmatched anonymous callbacks appear only under `--detail`.
3. Report what the numbers say in a sentence or two, and flag anything that looks off: a large
   `logic` share in a "docs only" change, a removed export, a function whose complexity jumped.
4. To record the table on the PR, run the same command with `--write`. It replaces the marked
   block if one exists, otherwise inserts a `## Change statistics` section before a trailing
   `<!-- sdlc-lease: ... -->` footer (which stays the last line), otherwise appends. It edits the
   PR body on GitHub, so confirm with the user first unless they asked for it. A failure to write
   is not a failure of the review: say so and go on.
5. Apply `after`.

## Accuracy

- **Exact:** the line totals, file counts, added/deleted/renamed/binary handling, the group split
  and the body splice.
- **Heuristic:** comment versus code is a one-line prefix test, so a Rust `#[derive]` reads as a
  comment, code after a closing `*/` on the same line counts as comment, and `#` comments in
  yaml or toml count as code. Treat those two rows as good to a few percent.
- **Heuristic:** the exported-API delta is a regex over declarations (first line only) plus an AST
  pass for class and interface members; a changed type below a wrapped parameter list is missed.
  Rust `pub` items are read the same way, without members.
- **Optional:** complexity for TypeScript and JavaScript uses the project's own `typescript`
  package, found from the working directory; without it, that part is skipped with a line saying
  so. Other languages need `lizard` on PATH. Class and interface members also need `typescript`.
- **Capped:** at most 150 files, 400 KB each and 20 seconds for the content passes. Anything
  skipped is named in the output, never dropped silently.

## Grading

- Does the report name the PR or range it measured?
- Is every number quoted from the script's output, none recomputed by hand?
- Were the heuristic parts described as approximate?
- Was the PR body left alone unless `--write` was asked for or confirmed?

## Test environment

In a scratch repository, commit a file, change it, commit again, and run
`node <skill-dir>/pr-stats.mjs --base HEAD~1`. Expect one `logic` file and, with `typescript`
reachable, a complexity row. Then run it from a directory that is not a git repository and expect
a one-line error, not a stack trace.
